# v0.2.1 — DSH bundle verification (configuration UI fix)

Date: 2026-10-18
Environment: DSH Desktop `44.7.0`, profile `desktop`, Windows, Python `3.14.6`, Node `24.18.0`

This release makes the `autoLoad` switch actually reachable and editable. v0.2.0 declared the Config schema but shipped no configuration UI, so the Plugins page had nothing to render. v0.2.1 fixes that path end to end:

- `autoLoad` is declared `.volatile()`. The Settings form layer projects only volatile fields, so without this the entry is never served as an editable form.
- The Client half registers a row configuration page at `plugins.row.config` for both the patch id and the composed loader entry id, giving the bundle row its **Configure** control.
- The same switch is rendered directly on **Settings → Team Protocol**, so it does not depend on finding the Plugins row.
- The `settings.section` registration now carries `locale`, fixing a blank page caused by a missing `t` reader.

The skill content is unchanged from v0.2.0 (`dsh_skill_snapshot` is identical).

## Configuration UI verification

1. The bundle row is active and its Config entry reports `status: schema`; the projected schema carries `x-cordis.volatile: true` for `autoLoad`.
2. `plugins.row.config` lists both registration keys active:
   `@conflagrationj/dsh-self-organizing-agent-team#self-organizing-agent-team` and `#include:self-organizing-agent-team`.
3. The **Settings → Team Protocol** page renders (previously blank) and shows the auto-load switch, checked by default.
4. Toggling the switch **off** wrote to the profile patch:

   ```yaml
   - id: self-organizing-agent-team
     name: "@conflagrationj/dsh-self-organizing-agent-team"
     config:
       autoLoad: false
   ```

5. With that override in place, a fresh subagent reported: *"No, my current context contains no block starting with `<skill_content name=\"self-organizing-agent-team\">`."*
6. Earlier, with auto-load on, a fresh subagent and a resumed session both contained the `<skill_content>` block, so both directions of the switch are observed.
7. Re-enabling the switch wrote `autoLoad: true` back to the same profile patch entry, so the setting is persisted, not client-only.

The Plugins bundle page exposes the same form through the row's **Configure** control (the chevron on the row).

## Known limits

- The value applies to agents created after the configuration change. Agents already created keep their section until they are recreated; a disabled value removes the section for new sessions, teammates, and subagents.
- The tarball is not byte-reproducible across gzip/zlib builds; trust the attached `SHA256SUMS` for it.
- The configuration page was verified visually through screenshots on the default locale; the second locale was not toggled in the UI.
- High-risk Agent Teams path (real writer/reviewer/executor with external side effects) remains a future forward test.
